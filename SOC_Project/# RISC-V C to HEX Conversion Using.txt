# RISC-V C to HEX Conversion Using Ubuntu

## 1. Update Ubuntu packages

Open the Ubuntu terminal and execute:

```bash
sudo apt update
```

## 2. Install RISC-V GCC Toolchain

Install the RISC-V GCC compiler and required binutils:

```bash
sudo apt install gcc-riscv64-unknown-elf binutils-riscv64-unknown-elf
```

## 3. Verify the installation

Check the GCC compiler:

```bash
riscv64-unknown-elf-gcc --version
```

Check the assembler:

```bash
riscv64-unknown-elf-as --version
```

Check the linker:

```bash
riscv64-unknown-elf-ld --version
```

Check the object copy utility:

```bash
riscv64-unknown-elf-objcopy --version
```

Check the disassembler:

```bash
riscv64-unknown-elf-objdump --version
```

Check the supported RISC-V architectures:

```bash
riscv64-unknown-elf-gcc --print-multi-lib
```

## 4. Create a project directory

```bash
mkdir riscv_c_project
```

Navigate into the directory:

```bash
cd riscv_c_project
```

## 5. Create a C program

Create a C source file:

```bash
nano test.c
```

Example C program:

```c
int main(void)
{
    volatile int a = 20;
    volatile int b = 10;

    volatile int addition;
    volatile int subtraction;

    addition = a + b;
    subtraction = a - b;

    while (1)
    {
    }

    return 0;
}
```

Save the file:

* Press `Ctrl + O`.
* Press `Enter`.
* Press `Ctrl + X` to exit Nano.

Verify the source code:

```bash
cat test.c
```

## 6. Compile C into an object file (.o)

```bash
riscv64-unknown-elf-gcc -march=rv32i -mabi=ilp32 -O0 -ffreestanding -fno-builtin -c test.c -o test.o
```

Check the generated object file:

```bash
ls -l
```

**Output:** `test.o`

## 7. Inspect the object file

Disassemble the object file to view the generated RISC-V instructions:

```bash
riscv64-unknown-elf-objdump -d test.o
```

## 8. Create a linker script

Create the linker script:

```bash
nano linker.ld
```

Add the following content:

```ld
ENTRY(main)

SECTIONS
{
    . = 0x00000000;

    .text :
    {
        *(.text)
        *(.text.*)
    }

    .rodata :
    {
        *(.rodata)
        *(.rodata.*)
    }

    .data :
    {
        *(.data)
        *(.data.*)
    }

    .bss :
    {
        *(.bss)
        *(.bss.*)
        *(COMMON)
    }
}
```

Save and exit Nano.

**Note:** This is a minimal linker script for the basic test. For actual SoC firmware, use the correct memory map and startup code.

## 9. Link the object file and generate ELF

Execute:

```bash
riscv64-unknown-elf-gcc \
-march=rv32i \
-mabi=ilp32 \
-nostdlib \
-nostartfiles \
-T linker.ld \
test.o \
-o test.elf \
-Wl,-Map=test.map
```

Generated files:

* `test.elf` – Executable ELF file.
* `test.map` – Linker map file.

## 10. Verify the ELF file

Check ELF header information:

```bash
riscv64-unknown-elf-readelf -h test.elf
```

Check section information:

```bash
riscv64-unknown-elf-objdump -h test.elf
```

Disassemble the linked ELF:

```bash
riscv64-unknown-elf-objdump -d test.elf
```

## 11. Convert ELF into HEX

Execute:

```bash
riscv64-unknown-elf-objcopy -O verilog test.elf test.hex
```

**Output:** `test.hex`

## 12. Verify the HEX file

Display the HEX contents:

```bash
cat test.hex
```

Check all generated files:

```bash
ls -lh
```

Expected files:

```text
riscv_c_project/
│
├── test.c
├── test.o
├── linker.ld
├── test.elf
├── test.map
└── test.hex
```

## 13. Store the output files separately (Optional)

Create an output directory:

```bash
mkdir -p output
```

Copy the generated files:

```bash
cp test.hex test.elf test.map output/
```

Verify:

```bash
ls -lh output/
```

---

# Complete Conversion Flow

```text
C Source File
     |
     | test.c
     v
RISC-V GCC Compiler
     |
     | test.o
     v
Linker + Linker Script
     |
     | test.elf
     | test.map
     v
ELF Inspection
     |
     v
RISC-V objcopy
     |
     | test.hex
     v
HEX File
     |
     v
SoC Memory / Simulation
```

# Important Notes

1. The compiler executable is named `riscv64-unknown-elf-gcc`, but it can generate RV32 code using the appropriate architecture and ABI options.
2. `-march=rv32i` and `-mabi=ilp32` were used for this basic example. Confirm the actual CPU ISA and ABI before compiling SoC firmware.
3. The linker script must match the SoC memory map.
4. Actual firmware may require startup assembly (`crt0.S`) to initialize the stack pointer and runtime memory.
5. The generated HEX format must match the memory initialization format expected by the SoC or simulator.
6. Successful HEX generation does not by itself guarantee that the firmware will execute correctly on the processor.

**Final conversion command:**

```bash
riscv64-unknown-elf-objcopy -O verilog test.elf test.hex
```
